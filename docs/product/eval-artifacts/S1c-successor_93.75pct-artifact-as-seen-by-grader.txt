“All three tests pass. Here's a summary of the changes: **`slugify.js`** — added an optional second argument `{ maxLength }`. After building the full slug, it slices to `maxLength` then strips any trailing hyphen the cut created. **Why truncate-then-trim, not trim-then-trim?** If you trimmed a trailing hyphen *before* truncating, you'd be operating on a shorter string, and after the subsequent cut a *different* hyphen could end up at the new tail — which you'd never see. By truncating to `maxLength` first, the slice is the last operation that can introduce a trailing hyphen, so a single `replace(/-+$/, "")` is guaranteed to clean it up correctly. **`slugify.test.js`** covers: - `"Hello World"` → `"hello-world"` (normal, no truncation) - `maxLength: 7` → `"hello-w"` (cuts mid-word, no hyphen issue) - `maxLength: 5` → `"hello"` (cut lands exactly on the hyphen, which is trimmed)”
